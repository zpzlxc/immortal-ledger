# 长生簿开发指导文档

> 版本：v0.1 MVP 规划  
> 游戏类型：单人、纯网页、文字冒险、轻度放置修仙  
> 当前目标：先做出一个可以每天打开几次、每次玩 1～5 分钟的可玩版本

## 1. 产品概述

### 1.1 游戏简介

玩家扮演一名资质普通的凡人，在有限寿元内踏上修仙之路。玩家通过修炼、探索、炼丹、经营洞府和处理人物关系逐步成长；离开网页后，角色仍会根据已安排的行动继续生活。

游戏的核心载体是一本会持续记录角色经历的“长生簿”。玩家每次回来，先阅读离线期间发生的日志，再做出一个重要选择，安排下一阶段行动。

### 1.2 核心卖点

- 碎片化游玩：打开页面即可继续，不要求持续在线。
- 文字驱动：主要内容由事件、选择、日志和数值变化组成。
- 有限寿元：每个决定都与时间和因果有关。
- 轻度放置：离线有收益，但不会因为错过一小时就严重落后。
- 多种人生路线：可以成为剑修、丹修、阵修或魂修，也可以成为不入宗门的散修。
- 轮回记录：角色死亡后，人生经历保存在长生簿中，为下一世提供少量长期解锁。

### 1.3 不做的事情

MVP 阶段明确不做以下内容：

- 多人在线、排行榜、公会和聊天。
- 复杂战斗动画、实时操作和音频依赖。
- 强制广告、体力倒计时和高频推送。
- 需要后端才能成立的账号体系。
- 大规模地图、3D 场景和复杂装备词缀。

## 2. 目标玩家与游玩场景

### 2.1 目标玩家

喜欢修仙题材、文字冒险、放置成长和收集剧情的单人玩家。玩家不需要长时间连续游玩，更重视“我的角色在我离开时发生了什么”。

### 2.2 单次游玩目标

一次打开网页应当能够在 1～5 分钟内完成：

1. 查看角色当前状态。
2. 阅读最近的行动结果和事件日志。
3. 做出一个有意义的选择。
4. 安排下一次行动。

### 2.3 使用体验要求

- 默认静音，文字和按钮必须能独立完成游戏。
- 页面刷新后状态不丢失。
- 手机和桌面浏览器均可阅读，但优先保证桌面窄窗口使用体验。
- 任何长期行动都必须允许玩家中途回来查看，不得阻塞页面。
- 离线收益需要有上限，避免修改系统时间带来过度收益。

## 3. 核心游戏循环

```text
打开网页
  ↓
结算上次离线期间的行动
  ↓
阅读长生簿日志
  ↓
做出事件选择或日常决策
  ↓
安排下一项行动
  ↓
关闭网页，等待角色继续生活
```

### 3.1 角色行动

MVP 提供五种行动：

| 行动 | 时间 | 主要收益 | 主要风险 |
| --- | --- | --- | --- |
| 平稳吐纳 | 10 分钟～8 小时 | 修为、少量心境 | 几乎无风险 |
| 极限运功 | 10 分钟～2 小时 | 更多修为 | 受伤、心境下降 |
| 采药探索 | 5～60 分钟 | 草药、灵石、事件 | 受伤、触发危险 |
| 洞府劳作 | 30 分钟～8 小时 | 灵田、聚灵阵、资源 | 消耗少量资源 |
| 研究功法 | 30 分钟～8 小时 | 功法进度、悟性 | 可能获得错误理解 |

行动结束后生成一条或多条日志。日志既是结果展示，也是后续剧情的入口。

### 3.2 事件选择

事件由“前置条件、正文、选项、结果”组成。每个事件至少提供两个选择，不能所有选择都只是不同数值收益。

示例：

> 你在枯井底部发现一枚染血玉简，神识触碰时听见微弱的求救声。

- 立即读取：可能获得功法，也可能被残魂影响。
- 带回洞府：消耗研究时间，结果更稳定。
- 出售给商会：立即获得灵石，但失去隐藏剧情。
- 埋回原处：增加某种因果记录，未来可能再次遇见它。

事件选择应当影响至少一项长期内容：属性、人物关系、因果、已发现地点、主线进度或未来事件池。

## 4. 世界与成长体系

### 4.1 境界

MVP 先实现前两个大境界，数据结构预留完整九境界：

1. 炼气
2. 筑基
3. 金丹
4. 元婴
5. 化神
6. 炼虚
7. 合体
8. 大乘
9. 渡劫

每个大境界分为初期、中期、后期、圆满。MVP 可以先使用“炼气一层～十二层”和“筑基初期”作为可见内容，避免首版只剩下空壳境界名称。

### 4.2 核心属性

| 属性 | 作用 |
| --- | --- |
| 修为 | 境界成长的主要进度 |
| 根骨 | 影响基础修炼效率和体魄相关事件 |
| 悟性 | 影响功法研究、事件领悟和突破准备 |
| 神识 | 影响探索、炼丹和识破危险 |
| 心境 | 影响突破成功率和走火入魔概率 |
| 气运 | 影响随机事件质量，不直接决定所有结果 |
| 寿元 | 角色可行动的生命时间，归零后结束本世 |
| 因果 | 连接人物、门派、隐藏剧情和结局 |

数值设计原则：

- 属性值在界面上必须能解释，避免只有玩家看不懂的隐藏公式。
- 关键事件结果优先使用区间和标签说明，不强行展示全部随机数。
- 数值增长要有明显阶段感，但不能让离线收益取代主动选择。

### 4.3 初始天赋

创建角色时从三个随机天赋中选择一个。首版提供六种天赋池：

- 凡骨：修炼效率低，但突破失败惩罚较轻。
- 灵脉初醒：吐纳收益较高，探索资源较少。
- 过目不忘：功法研究速度快。
- 山野药心：采药和炼丹更稳定。
- 天生剑意：战斗和危险探索更有优势。
- 命犯孤星：气运波动大，隐藏事件更多。

天赋不能让角色直接跳过成长路线，应当改变玩法倾向，而不是决定胜负。

## 5. 主要系统

### 5.1 修炼系统

修炼结果由基础效率、行动时长、功法加成、洞府加成和随机事件共同决定。

平稳吐纳是最可靠的默认行动；极限运功收益更高，但只有在心境或功法条件合适时才值得使用。

MVP 先实现：

- 平稳吐纳。
- 极限运功。
- 行动完成后增加修为并生成日志。
- 心境过低时给出风险提示。

### 5.2 探索系统

MVP 提供三个地点：

- 青石山：低风险，获得草药和基础灵石。
- 黑风谷：中风险，可能获得特殊功法残页。
- 无名古井：主线地点，事件数量少但与长生簿秘密有关。

每个地点包含独立事件池、推荐境界、危险标签和可获得资源。探索不要求逐格移动，玩家只选择地点和探索时长。

### 5.3 洞府系统

洞府是资源生产和长期计划中心。MVP 只做三个建筑：

- 聚灵阵：提高修炼收益。
- 灵田：定时产出基础草药。
- 藏经阁：减少功法研究时间。

建筑升级消耗灵石和材料，最多先做三级。建筑收益在离线结算时统一计算。

### 5.4 功法与流派

当前 MVP 已实现四条流派标签和四门入门功法，每门功法都带三段研究分支：

- 剑修：通过探索灵石加成，偏向山野和险地收益。
- 丹修：通过研读残页和熟练度加成，偏向稳定研究成长。
- 阵修：通过修炼收益加成，后续可继续与洞府建筑联动。
- 魂修：通过更快的熟练度成长，偏向研究分支推进。

当前已实现名称、品阶、当前熟练度、分支效果、熟练度前置条件和残页消耗。功法学习通过选择流派和研究完成，不做成单纯装备替换；多门功法并修、流派专属剧情和风险标签仍放到后续版本。

### 5.5 人物与宗门

当前 MVP 已加入三个重要人物：

- 林秋：善于交易，帮助玩家获得资源。
- 玄松道人：提供功法和突破建议。
- 残魂“无名”：与主线秘密相关，但可能带来因果风险。

人物关系使用四种状态：陌生、熟悉、信任、敌对。探索、研读和无名古井会触发一次性人物事件，玩家的选项会改变好感、资源、属性和因果，并写入长生簿。

宗门当前实现三座门墙：青霄剑宗、百草谷、天机阁。玄松道人事件可以提供引荐，玩家只能加入一座宗门；入门后获得专属修炼、探索或研读效果，并按完成行动累计宗门贡献。完整宗门声望、职位、叛门机制和宗门专属剧情放到后续版本。

### 5.6 寿元、死亡与轮回

寿元是游戏的时间压力来源，但不应让玩家因为几次错误选择就失去全部体验。

角色死亡原因包括：寿元耗尽、渡劫失败、严重伤势和特殊剧情。MVP 只实现“寿元耗尽”和“探索重伤”两种结束方式。

死亡后生成一份本世总结：

- 本世境界。
- 最长连续修炼记录。
- 重要人物关系。
- 已发现地点和秘密。
- 关键选择。
- 死亡原因。

下一世可以继承已解锁的世界图鉴和一项微小的“前世遗泽”，但不能直接继承大量修为，避免轮回变成跳过游戏。

## 6. 离线结算规则

### 6.1 结算模型

保存以下时间字段：

- `lastSettledAt`：上次结算时间。
- `currentAction.startedAt`：行动开始时间。
- `currentAction.endsAt`：行动预计结束时间。
- `currentAction.type`：行动类型。

打开页面时：

1. 读取本地存档。
2. 计算当前时间与 `lastSettledAt` 的差值。
3. 只结算已完成的行动和定时建筑。
4. 将新的结算时间写回存档。
5. 生成离线日志。

### 6.2 安全边界

- 单次离线收益最多结算 8 小时。
- 时间倒退时不发放收益，并记录一条本地诊断日志。
- 行动完成后只结算一次，不能刷新重复领取。
- 结算逻辑必须是纯函数，方便测试。
- MVP 使用浏览器本地时间；未来接入后端后再引入服务端时间。

### 6.3 设计目标

离线收益应当让玩家回来时有“角色继续生活”的感觉，但主动回来做选择的收益必须更高。不要让玩家每天只打开一次也能获得全部成长。

## 7. 数据模型建议

MVP 可以使用 TypeScript 类型和 `localStorage`，不需要后端数据库。

```ts
type Realm = {
  major: 'qi_refining' | 'foundation_establishment';
  stage: number;
  cultivation: number;
  cultivationRequired: number;
};

type Character = {
  id: string;
  name: string;
  createdAt: string;
  age: number;
  lifespan: number;
  attributes: {
    physique: number;
    comprehension: number;
    spiritSense: number;
    mentalState: number;
    fortune: number;
    karma: number;
  };
  realm: Realm;
  talents: string[];
  currentAction: Action | null;
};

type Action = {
  id: string;
  type: 'meditate' | 'overdrive' | 'explore' | 'cultivate_field' | 'study';
  locationId?: string;
  startedAt: string;
  endsAt: string;
  status: 'running' | 'completed' | 'cancelled';
};

type LedgerEntry = {
  id: string;
  createdAt: string;
  category: 'action' | 'event' | 'breakthrough' | 'relationship' | 'death';
  title: string;
  body: string;
  choices?: Choice[];
  tags: string[];
  read: boolean;
};

type SaveData = {
  schemaVersion: number;
  lastSettledAt: string;
  character: Character;
  inventory: Record<string, number>;
  buildings: Record<string, { level: number; lastCollectedAt: string }>;
  relationships: Record<string, number>;
  discoveredContent: string[];
  ledger: LedgerEntry[];
};
```

### 7.1 存档要求

- 所有存档写入使用一个版本化根对象。
- 读取旧版本时执行迁移，不直接假设字段永远存在。
- 每次重大操作前保存一次。
- 增加“导出存档”和“导入存档”按钮，方便个人游玩时备份。
- 导出格式为 JSON，文件名包含角色名和日期。

## 8. 页面与交互设计

### 8.1 页面结构

首版只需要四个主要区域：

1. **主界面 / 长生簿**：时间线、最近日志、当前事件。
2. **修炼**：选择功法和修炼方式，安排行动。
3. **洞府**：查看建筑、资源和升级。
4. **人物与图鉴**：查看关系、地点、功法和已发现秘密。

### 8.2 主界面信息层级

首屏必须直接展示：

- 角色名和当前境界。
- 当前年龄 / 寿元。
- 当前行动及剩余时间。
- 未读日志数量。
- 一个最重要的待处理事件。

次要信息放入折叠面板，避免打开页面后被大量数值淹没。

### 8.3 文字风格

- 系统说明使用现代、清晰的中文。
- 事件正文使用简洁的古风叙事，但不要堆砌生僻词。
- 选项按钮直接说明行为，不使用“选项一、选项二”。
- 数值变化用短标签展示，例如“修为 +12”“心境 -3”。
- 危险选项必须明确提示风险等级，但不直接剧透所有结果。

## 9. 推荐技术方案

### 9.1 MVP 技术边界

推荐使用：

- Vite
- React
- TypeScript
- CSS Modules 或普通 CSS
- `localStorage` 存档
- Vitest 测试核心结算逻辑

首版不引入后端、数据库、用户登录和复杂状态管理库。游戏状态规模小，使用集中式 `GameStore` 或 React Context 即可。

### 9.2 目录建议

```text
src/
  app/
    App.tsx
    routes.ts
  components/
    ActionPanel/
    CharacterStatus/
    LedgerTimeline/
    ChoicePanel/
    OfflineSummary/
  game/
    actions.ts
    events.ts
    progression.ts
    settlement.ts
    save.ts
    types.ts
  content/
    talents.ts
    locations.ts
    techniques.ts
    characters.ts
  styles/
    theme.css
  main.tsx
docs/
  game-development-guide.md
```

### 9.3 代码边界

- `game/` 只负责规则，不直接操作 DOM。
- `content/` 只负责内容数据，不写结算逻辑。
- React 组件只负责展示和触发命令。
- 离线结算、突破判定、奖励生成必须可脱离浏览器单元测试。
- 所有随机数逻辑都允许注入随机源，测试时使用固定随机数。

## 10. MVP 开发拆分

### Milestone 0：项目骨架

- 创建前端项目。
- 建立基础布局和路由。
- 实现本地存档读写。
- 放入一份默认测试角色。

验收：刷新页面后角色名、境界和日志仍然存在。

### Milestone 1：长生簿与行动

- 实现角色状态卡。
- 实现平稳吐纳和极限运功。
- 实现行动倒计时。
- 实现关闭页面后再次打开的结算。
- 实现日志时间线。

验收：玩家可以完成一次行动、刷新页面、看到一次且仅一次的结算日志。

### Milestone 2：探索与选择

- 加入三个探索地点。
- 实现至少十个事件。
- 实现事件选项和条件判断。
- 实现物品、修为、心境、因果变化。

验收：同一地点可以产生不同事件；选择至少会影响两种不同的长期状态。

### Milestone 3：突破与洞府

- 实现炼气境界和突破事件。
- 实现聚灵阵、灵田、藏经阁。
- 实现资源消耗和建筑升级。
- 实现突破成功、失败和日志记录。

验收：玩家可以从炼气一层成长到炼气圆满，并在条件满足后尝试筑基。

### Milestone 4：人物、死亡与备份

- 加入三个重要人物。
- 实现关系值和人物事件。
- 实现寿元耗尽。
- 实现本世总结和新建下一世。
- 实现存档导出与导入。

验收：角色结束一世后，历史仍可查看；下一世能继承少量图鉴或遗泽。

## 11. 测试与验收标准

### 11.1 规则测试

必须覆盖：

- 行动未结束时不能重复领取。
- 行动结束后刷新页面不会重复领取。
- 时间差超过 8 小时时只结算 8 小时。
- 时间倒退时不会增加资源。
- 修为达到阈值后才能突破。
- 心境过低时突破风险上升。
- 寿元归零后不能继续安排行动。
- 导出再导入后存档结果一致。
- 旧存档版本能够正常迁移。

### 11.2 手工体验测试

- 首次打开后，玩家应在 30 秒内知道下一步做什么。
- 不阅读额外说明，也能理解“当前行动”和“剩余时间”。
- 每次回来都有可读的变化，而不是只有一串数字。
- 事件正文在桌面窄窗口下不溢出。
- 手机端按钮可点击，重要日志不被截断。
- 误触危险选项前有清晰提示。

### 11.3 完成定义

MVP 只有同时满足以下条件才算完成：

- 可创建角色、行动、离线结算、探索、突破和结束一世。
- 存档刷新不丢失，导出导入可用。
- 核心结算逻辑有自动化测试。
- 至少有 20 条可读日志和 10 个带选择的事件。
- 玩家可以在不看开发者控制台的情况下完成一次完整循环。

## 12. 后续版本方向

MVP 稳定后再考虑：

- 更多境界、宗门和地图。
- 剑修、丹修、阵修、魂修完整路线。
- 季节、天气、天象和周期性秘境。
- 更丰富的人物关系和多结局主线。
- PWA 安装、桌面通知和跨设备同步。
- 可选后端账号与云端存档。

后续所有扩展都应遵守一个原则：增加新的选择和故事，不只是增加更大的数值。

## 13. 开发优先级

按以下顺序开发，不要在首版提前扩展世界观：

1. 存档和时间结算。
2. 长生簿日志展示。
3. 修炼行动。
4. 探索事件和选择。
5. 境界突破。
6. 洞府和资源。
7. 人物关系。
8. 死亡、轮回和主线秘密。

首版最重要的体验不是“内容很多”，而是：

> 玩家离开网页一段时间后，再回来时，确实能感受到自己的角色活过了一段时间，并且眼前有一个值得做出的选择。
