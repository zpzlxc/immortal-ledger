# 长生簿：页面优化与后续路线

更新：2026-09-08。依据当前源码与本地页面检查整理，以下未勾选的功能是规划，不代表已交付。

## 本轮交付

- 保留现有水墨场景，以纸色、朱砂印章、细边框和更清晰的正文对比度统一页面。
- 首页增加「今日一笺」及直达入口，根据待处理事件、伤势、洞府收成、当前行动、关隘和开局进度给出建议。
- 桌面导航与内容改为独立布局行，滚动时不再遮挡主视觉；移动端导航单行横向滚动并吸顶。
- 顶部导入导出合并为「存档管理」，手机端显示云存档状态和完整资源名称。
- 登录与同步错误分开反馈，游戏页提供失败重试；登录表单显示输入要求，支持 Escape 关闭和焦点循环。
- 导入存档前确认角色与覆盖范围；本世足迹改为完成数量描述，避免把非顺序里程碑误报为线性进度。

## 建议顺序

### 1. 存档可信度与恢复体验（优先）

目前后端有版本号与历史记录，但前端仍自动采用云端冲突版本，且上传队列没有按账号或同步批次隔离。先补齐以下能力，目标是让玩家始终知道哪份进度正在使用：

- [ ] 冲突比较：角色名、境界、保存时间、进度差异，允许先下载本地副本再选择。
- [ ] 上传队列绑定账号与会话；登出、换号、重置或发生冲突时作废旧任务与迟到响应。
- [ ] 最近 30 个版本的列表、预览与恢复入口；恢复本身生成新版本。
- [ ] 自动重试明确区分网络错误与鉴权失效，并显示最近成功同步时间。
- [ ] 创建角色页和本世终章共享账号及同步面板。

验收：两设备同时写、弱网重试、登出后迟到响应、切换账号时队列未清空均不串档；玩家可以找回自己选错的版本。

### 2. 人物与剧情的视觉表达（下一轮视觉重点）

现有角色肖像、关系事件和多章剧情已经具备基础，适合深化阅读体验。

- [ ] 人物页采用书信/人物小传呈现：肖像、关系、最近互动与待处理事件分层。
- [ ] 剧情按章节回看，保留已作选择与人物回应；未解锁内容避免提前剧透。
- [ ] 选择按钮展示明确成本与已知风险，隐藏未知剧情结果。
- [ ] 增加克制的揭页、落印动效，并尊重减少动态效果设置。

验收：390px 手机上无需来回滚动就能理解当前事件和选项；不同剧情状态、长文本和空状态均有完整排版。

### 3. 提高第二世、第三世的差异

主辅功法、联动冲突、轮回遗泽、跨世目标已经存在。适合从这些系统继续扩展：

- [ ] 每种流派增加一条独有剧情与一项可感知的取舍。
- [ ] 前世选择改变下一世的遇人、开局目标或事件解法。
- [ ] 本世总结增加路线回顾，呈现玩家具体改变了什么。

验收：玩家更换流派或遗泽后，前 30 分钟就能体验不同选择，而不仅是收益百分比变化。

### 4. 再深化资源循环与随手游玩

- [ ] 聚灵阵、灵田专属事件与分支生产链，使满级后仍有目标。
- [ ] 根据完整的一世游玩数据调整资源缺口和行动时长；先记录再调数值。
- [ ] PWA 安装、离线启动和可选提醒。离线时明确说明哪些功能不可用。

验收：离线启动不丢进度；低阶资源后期仍有用途；提醒可独立关闭。

## 暂缓的方向

多人交易、排行榜、竞技和大规模新境界建议放在存档恢复与服务端可信结算之后。当前规则由浏览器执行，直接加入排名或交易会放大篡改与一致性问题。

## 工程配套

随功能拆分 App.tsx 中的账号、存档面板、页面组件与引导规则；避免在每秒结算的 React 状态更新函数中混入网络副作用。逐步补充跨账号、冲突恢复及长时间离线浏览器回归。

## 本轮验证

- 全量 69 项测试通过；Worker 类型检查、Worker 前端构建通过。
- 本地生产构建在 1440px 桌面与 390px 移动视口检查，无整页横向溢出。
- 验证「今日一笺」跳转探索、登录表单必填要求及 Escape 关闭。
- 本轮为本地页面优化，未部署到线上、未提交或推送 Git。账号及同步错误处理的线上弱网/多设备回归仍属于下一阶段。
